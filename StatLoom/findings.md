# Findings & Decisions

## Requirements
<!-- 从用户请求与《项目框架.md》提取 -->

- 在 test/ 目录下实现 StatLoom 最小原型（用户明确指定位置）。
- 原型必须覆盖框架第 7 节的七件事：
  1. 可编辑的数据集
  2. 分组分布视图
  3. 一组实时更新的统计量
  4. 可展开、可分支、可反向追踪的公式推导面板
  5. 可切换损失函数的交互画布
  6. 与当前对象关联的知识卡片
  7. 可选的预测—验证机制
- 走通一条完整探索路径（框架验证标准，六条）：
  - 不掌握统计术语也能开始操作
  - 操作产生真实、可理解的数学反馈
  - 能从结果追踪到公式与原始数据
  - 推导允许停留、展开、分支
  - 知识解释保持与当前对象的联系
  - 全部引导可忽略、可退出
- 验证场景：教学方式×考试成绩 CSV，六阶段（观察→行动→发现与追踪→展开推导→改变分析目标→深入知识）。

## Research Findings
<!-- 探索中的关键发现 -->

- 工作区现状：项目根下有两份设计文档 + 《项目框架.md》；test/ 为空目录。
- 环境：Python 3.13.15、Node v24.16.0、npm 11.13.0 均可用；平台 Windows 11，shell 为 Git Bash。
- 目录不是 git 仓库。
- ES Modules 在 file:// 协议下受 CORS 限制无法加载，需要本地 HTTP 服务；用 `python -m http.server` 解决，写 start.bat 一键启动。
- 验证手段：无 puppeteer 等依赖，用 `node --check` 做语法检查，用 Edge/Chrome 无头模式 `--screenshot` / `--dump-dom` 做渲染检查。

## Technical Decisions
| Decision | Rationale |
|----------|-----------|
| 原生 ES Modules + SVG，零依赖零构建 | 最小原型验证交互；避免安装依赖；统计图（点图、损失曲线）用 SVG 手绘即可 |
| stats.js 纯函数统计引擎，与视图解耦 | 对应框架"数学语义、计算逻辑与可视化实现相互解耦"；可被 Node 直接测试 |
| 单一 store + 订阅通知（pub/sub）驱动视图 | 数据、视图状态（选中项、追踪焦点）集中管理，满足双向追踪的跨视图联动 |
| 快照撤销栈 | 对应"操作可随时撤销或返回原始状态" |
| 异常值提示用 IQR 规则并注明"这是规则提示、不代表数据错误" | 对应红线"潜在异常值不标记为错误数据" |
| 混合分组：保留原始分布幽灵叠影 + 前后数值对照 | 对应"系统保留原始分组视图，允许用户在混合前后进行比较" |
